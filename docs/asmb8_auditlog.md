# `asmb8_auditlog`

Read the ASMB8-iKVM BMC's audit log and its logging configuration.
Read-only.

## Synopsis

Reads four read-only `.asp` endpoints: `getauditlog.asp` (the audit log
entries themselves), `getauditlogcfg.asp` (where the audit log is mirrored to
— a remote share/SD card), `getlogcfg.asp` (general audit/syslog enablement
and rotation), and `getselcfg.asp` (the IPMI SEL overflow policy).

**`entries` is returned verbatim, and is not sanitised.** Each entry is free
text generated by BMC firmware describing an operator action — a login, a
configuration change, a session event — and routinely names a real username
and a real source address, exactly as the fixture corpus's one captured
entry does (`Aug 11 00:48:53 localhost webgo: [2615 INFO]WEBGUI user admin
login successfully from 192.0.2.10`). This module does not attempt to
redact, truncate, or reinterpret that text: doing so would corrupt the record
this endpoint exists to provide and give a false sense that identifying
detail had been removed when a firmware revision this corpus has not seen
might phrase an entry differently. **Treat `entries` the same way you would
treat any other export of a real audit trail**: do not print it to a public
build log, paste it into a public issue, or otherwise send it somewhere
public without thinking about what a specific entry's own text actually
contains.

**A specific parsing hazard this module inherits protection against, not
invents.** The fixture's one real captured entry contains the literal
characters `[` and `]` *inside* its own quoted string value (`[2615 INFO]`
is part of the log line, not array syntax). This module does not parse
`.asp` responses itself — it calls `module_utils/asp.py`'s
`AspClient.get_webvar()`, which delegates to `module_utils/webvar.py`'s
quote-aware scanner, the component actually responsible for not mistaking
that embedded `]` for the end of the response's array.

**No credential ever appears in this module's output, by construction.**
`getauditlogcfg.asp`'s one record carries a `PWORD` field for the remote
share's own authentication — this module never reads that field into
`remote_storage`, only whether it is non-empty, as
`remote_storage.password_configured`. `remote_storage.username` is a plain
username (`UNAME`), not a password, and is returned as read.

**`remote_storage.address` and `logging.remote_syslog_address` are
environment detail, returned exactly as the BMC reports them, with no
redaction performed by this module.** The fixture corpus shows both as empty
strings (no remote log destination configured on the captured board) — that
is not evidence a populated address would look like anything in particular.
Do not build automation, or a test, that assumes a real address here is
IPv4-shaped, always populated, or has any other inferred property.

**This module never writes anything, and there is no option anywhere in it
that would.** Clearing this BMC's audit log, or changing where it is
mirrored to, is deliberately absent from this release: a cleared audit log
destroys evidence, and there is no way to tell, after the fact, whether that
was intentional cleanup or exactly the action an operator most needed a
record of. Adding a write path for either needs its own explicit review that
this module does not attempt to shortcut.

## Options

| Option | Type | Default | Required | Choices |
|---|---|---|---|---|
| `host` | `str` | — | yes | — |
| `port` | `int` | `443` | no | — |
| `username` | `str` | `admin` | no | — |
| `password` | `str` (`no_log`) | — | yes | — |
| `use_tls` | `bool` | `true` | no | — |
| `allow_insecure_transport` | `bool` | `false` | no | — |
| `validate_certs` | `bool` | `true` | no | — |
| `ca_path` | `path` | — | no | — (mutually exclusive with `tls_fingerprint`) |
| `tls_fingerprint` | `str` | — | no | — (mutually exclusive with `ca_path`; recommended trust mode for this board) |
| `timeout` | `int` | `30` | no | — |
| `connect_timeout` | `int` | `10` | no | — |

This module takes only the shared connection options. Verified against
`argument_spec()` in `plugins/modules/asmb8_auditlog.py`.

## Return values

| Field | Type | Returned | Description |
|---|---|---|---|
| `changed` | `bool` | always | Always `false`. |
| `entries` | `list` of `str` | when available | Every `AUDIT_LOG` entry `getauditlog.asp` returned, in order, exactly as written by the BMC. **Not sanitised** — may contain real usernames or source addresses. |
| `remote_storage.remote_enabled` / `.sd_card_enabled` | `bool` | when available | `RM_ENABLE`, `SD_ENABLE`. |
| `remote_storage.remote_status` / `.sd_card_status` | `int` | " | Raw `REMOTE_STATUS`, `SDCARD_STATUS`. |
| `remote_storage.address` / `.remote_path` / `.share_type` | — | " | `IP_ADDR` (unredacted, see module description), `REMOTE_PATH`, `SHR_TYPE`. |
| `remote_storage.username` | `str` | " | `UNAME`, returned as read. A plain username, not a password. |
| `remote_storage.password_configured` | `bool` | " | Whether `PWORD` is non-empty, **not** its value. The actual password is never read into this module's output. |
| `remote_storage.domain_name` | `str` | " | `DOMAIN_NAME`. |
| `logging.audit_enabled` / `.syslog_enabled` | `bool` | when available | `AUDITENABLE`, `SYSLOGENABLE`. |
| `logging.file_size` / `.rotate_count` | `int` | " | `FILESIZE`, `ROTATECNT`. |
| `logging.remote_syslog_address` | `str` | " | `SERVERADDR`, unredacted — see the module description. |
| `sel_policy` | `int` | when available | `getselcfg.asp`'s raw `SEL_POLICY` value. |
| `operation.schema` | `str` | always | Always `"asmb8-ikvm-operation/v1"`. |
| `operation.action` | `str` | always | Always `"asmb8_auditlog.read"`. |
| `operation.endpoint` | `str` | always | The `host:port` this read was performed against. |
| `operation.changed` | `bool` | always | Always `false`. |
| `operation.error_class` | `str` | always | `null` on success. |
| `operation.endpoint_reads.<field>.outcome` / `.error_class` | `str` | always | Per-endpoint `read`/`failed` outcome for each of the four source endpoints, keyed by the field it feeds (`entries`, `remote_storage`, `logging`, `sel_policy`). One endpoint failing does not fail the whole module once the `.asp` session is established. |

Verified against the `RETURN` block in `plugins/modules/asmb8_auditlog.py`,
and against `tests/unit/fixtures/asp/getauditlog.txt`,
`getauditlogcfg.txt`, `getlogcfg.txt`, and `getselcfg.txt`.

## `error_class` values this module can raise

- `connection` / `tls_validation` / `authentication` / `timeout` / `bmc_busy`
  — establishing the `.asp` session itself (login), via the same `AspClient`
  machinery `asmb8_media` uses. This fails the whole module.
- Any of the above, per endpoint, once logged in — caught internally and
  reported through `operation.endpoint_reads` instead of failing the module;
  see the module description.

## Check-mode behaviour

Full support. A full read runs identically in check mode, since this module
never mutates board configuration. `diff_mode` is not supported.

## Example

```yaml
- name: Read the audit log and its logging configuration
  james_crowley.asmb8_ikvm.asmb8_auditlog:
    host: "{{ asmb8_host }}"
    username: "{{ asmb8_username }}"
    password: "{{ asmb8_password }}"
    tls_fingerprint: "{{ asmb8_tls_fingerprint }}"
  delegate_to: localhost
  no_log: true
  register: auditlog

- name: Fail the play if the audit log is disabled
  ansible.builtin.assert:
    that:
      - auditlog.logging.audit_enabled

- name: Do NOT do this in a public-facing log -- entries may contain usernames/addresses
  ansible.builtin.debug:
    msg: "{{ auditlog.entries }}"
  when: false # illustrative only; see this module's description
```
